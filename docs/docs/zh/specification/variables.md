# 变量

## 在 MarkdownFlow 中使用变量

变量是 MarkdownFlow 中为共享上下文命名的进阶方式。它们作为占位符，在处理时被替换为实际值。

对于大多数单文档 MarkdownFlow 体验，交互控件**不需要**变量。直接写 `?[选项 A | 选项 B]` 或 `?[...输入提示]`，然后在后续提示词中自然引用用户的回答即可。当某个值由平台提供，或需要跨不同 MarkdownFlow 文档共享时，才使用变量。

## 基本语法

变量使用双大括号：

```markdown
{{变量名}}
```

**共享上下文示例：**

```markdown
向 {{用户名}} 打招呼，并提醒他们当前账户余额为 {{余额}}。
```

## 变量命名规则

变量名是**文本键**，不作为编程语言的标识符或表达式解释。引用 `{{名称}}` 和赋值 `%{{名称}}` 使用相同规则：

1. 从 `{{` 读取到**第一个字面的 `}}`**。标记内部的 `{{` 不会递归解析。
2. 去掉名称两端的空白字符（trim），结果不能为空。
3. 其余内容逐字保留，包括内部空格、连续空格、标点、Unicode 字符、表情符号、方括号、引号和反斜杠。名称区分大小写，不进行 Unicode 或标点归一化。
4. trim 后的名称不能包含控制字符（U+0000–U+001F 或 U+007F–U+009F）、U+2028、U+2029，也不能包含保留的结束序列 `}}`。

引号不表示特殊的引用语法，反斜杠也不会在名称中引入转义。`{{"name"}}` 使用包含双引号的键 `"name"`，`{{path\}}` 使用以反斜杠结尾的键。`{{name[0]}}` 和 `{{user.name}}` 都是字面键名，不表示数组索引或属性访问。

trim 使用明确的跨语言空白字符集：U+0009–U+000D、U+001C–U+0020、U+0085、U+00A0、U+1680、U+2000–U+200A、U+2028–U+2029、U+202F、U+205F 和 U+3000。U+FEFF 保留为键内容。先 trim，再检查控制字符；内部空白不合并。

### 示例

| 标记 | 精确键名 |
| --- | --- |
| `{{user_name}}` | `user_name` |
| `{{ name }}` | `name` |
| `{{user name}}` | `user name` |
| `{{user  name}}` | `user  name`（两个内部空格） |
| `{{你的性别是？}}` | `你的性别是？` |
| `{{🚀 rocket}}` | `🚀 rocket` |
| `{{a{b}c}}` | `a{b}c` |
| `{{ a} }}` | `a}` |
| `{{outer{{inner}}` | `outer{{inner`（不解析嵌套） |

`{{}}` 和 `{{   }}` 的 trim 结果为空，因此无效。名称内部不能包含换行或控制字符。当前语法无法表达包含字面 `}}` 的键：`{{a}}b}}` 会被解析为键 `a`，后面跟随文本 `b}}`。该结束序列没有额外的转义或引号写法。

生成标记时，应在键的两侧各加一个空格：`{{ 键 }}` 或 `%{{ 键 }}`。这样能保留以单个 `}` 结尾的名称，无需新增转义语法。无效或空标记按普通文本保留，解析器不能从其内部继续提取嵌套变量。

### 命名交互

每个变量标记都作为**一个完整的 token** 解析，然后再解释交互边界和操作符。标记内部的 `]` 不结束交互，`|` 不分隔选项，`//` 不引入选项值，`...` 不引入输入框。只有交互开头（可有前置空白）的赋值标记命名当前交互的答案；位于选项内的标记不会给当前答案赋值。

控件外也遵循同样的保护规则：`{{ key ?[A|B] }}` 是一个变量标记，不是交互。未闭合的变量标记将剩余内容保留为普通文本，不再从其内部识别控件。

```markdown
询问用户希望选择的学习路径和级别。
?[%{{ 学习[路径] | 级别//提示...？ }} 概念//concepts | 示例//examples]

在下一个文档中，根据 {{ 学习[路径] | 级别//提示...？ }} 调整教学内容。
```

两个标记使用同一个精确键名 `学习[路径] | 级别//提示...？`。只有赋值标记结束后的操作符才描述按钮。

### Markdown 字面量边界

保留 Markdown 行内代码、完整行内公式和行内链接资源部分（目标地址及标题）、围栏和缩进代码块、完整 HTML 标签，以及 `script`、`style`、`pre`、`textarea` 原始 HTML 块原有的边界。其中展示的变量写法不能越过所属上下文，遮蔽后面的变量或控件。代码和公式的分隔符不能跨空段落、后续围栏代码块或 ATX 标题边界配对。原始 HTML 块包含结束标签所在的完整一行。为兼容已有提示词，文档变量提取仍收集原本支持的完整示例标记，包括行内代码、HTML 标签和代码围栏语言信息中的标记；各平台保留原有的代码块排除规则。应在各个上下文内独立读取。按照 Markdown 规则用反斜杠转义左花括号后，该字符不再开启变量标记。

列表和引用容器中的代码围栏保留 Markdown 边界。`<div>` 等普通 HTML 块在下一个空行结束；上述四类原始 HTML 块则在结束标签所在行之后结束。LF、CRLF 和 CR 都作为物理换行处理，不改写标记原文或源码偏移。

例如，``展示 `{{`，然后 ?[%{{ q }} A|B]`` 声明 `q`，并包含一个交互。``展示 `%{{ q }}`，然后 ?[A|B]`` 仍声明 `q`，其中的行内代码在渲染时保持字面量。在普通文本中，一旦识别出变量标记，其内部的反引号、HTML 和用作前后空白的换行均属于标记内容；该处真正未闭合的标记仍占据后续全部内容。

### 兼容性

原有字母、数字和下划线键名保持不变。`{{name}}`、`{{ name}}` 和 `{{ name }}` 使用相同的键。已有的标点、引号和反斜杠键不会被解码或重命名，不迁移已存记忆。

新规则也会识别旧实现可能按普通文本处理或拒绝的名称，例如 `{{user name}}`。升级解析器时，应检查展示变量写法的示例文本。旧版 SDK 可能曾错误地收集或替换 Markdown 转义后的起始符，文档处理现在将该起始符保留为字面量。历史上的畸形标记，以及内部含控制字符的名称，不属于有效语法。

语法不规定固定的名称长度。平台可以在规范化后另行检查存储或请求长度限制，但不能静默截断键名。旧版 SDK 可能尚不支持扩展规则，采用新规则的实现应通过共享样例。

[共享一致性样例](../../assets/variable-name-cases.json)提供名称 trim、变量提取、交互解析和文档上下文的共同验收数据。

## 变量如何工作

### 1. 来源

变量从多个来源获取它们的值：

**用于跨文档共享的命名交互输入：**

```markdown
请用户输入一个需要提供给后续 MarkdownFlow 文档的资料名称。
?[%{{共享资料名称}} ...请输入您的姓名]

在另一个 MarkdownFlow 文档中，为 {{共享资料名称}} 生成温暖的问候。
```

不要给普通的单文档交互添加 `%{{变量名}}`。命名变量形式用于共享状态。

**系统预定义变量：**

系统变量由平台预先定义，无需用户输入即可直接使用。不同平台提供不同的系统变量：

**[MarkdownFlow Playground](https://play.mdflow.run)：**

- `{{browser_language}}` - 用户的浏览器语言（例如 "en-US"、"zh-CN"）

**[AI-Shifu Platform](https://ai-shifu.com)：**

- `{{sys_user_nickname}}` - 用户的显示名称
- `{{sys_user_style}}` - 用户偏好的内容风格
- `{{sys_user_background}}` - 用户的背景信息
- `{{sys_user_language}}` - 用户的语言偏好

### 2. 变量替换

在 LLM 处理内容之前，MarkdownFlow 智能体会将所有变量替换为实际值：

```markdown
之前："为正在以 {{水平}} 水平学习 {{主题}} 的 {{用户名}} 生成个性化问候。"
之后："为正在以 初级水平 学习 Python 的 张三 生成个性化问候。"
```

然后 LLM 处理这个解析后的提示词，为读者生成实际内容。

### 3. 未赋值的变量

如果变量尚未赋值，将被替换为 "UNKNOWN"：

```markdown
之前："为对 {{主题}} 感兴趣的 {{用户类型}} 生成内容。"
之后："为对 UNKNOWN 感兴趣的 UNKNOWN 生成内容。"
```

**重要提示：** 请确保在使用变量前为其赋值（通过共享交互状态或系统默认值），避免提示词中出现 "UNKNOWN"。当 LLM 接收到含有 "UNKNOWN" 的提示词时，可能会产生不可预测的结果。

## 不同上下文中的变量

当您使用共享变量时，它们可以出现在文档中的任何位置：

### 在文本中

```markdown
生成一个让 {{用户名}} 感到亲切的个性化欢迎词。
```

### 在标题中

```markdown
# 第 {{章节编号}} 章：{{章节标题}}
```

### 在列表中

```markdown
以清晰的列表格式总结用户的产品选择：
- 选择的颜色：{{选定颜色}}
- 选择的尺寸：{{选定尺寸}}  
- 期望的数量：{{数量}}
```

### 在链接和图片中

```markdown
[访问 {{网站名称}}]({{网站网址}})
![{{图片描述}}]({{图片路径}})
```

### 在表格中

```markdown
创建一个格式化表格展示用户的账户信息：
| 属性 | 值 |
| ---- | --------------------- |
| 姓名 | {{用户名}} |
| 邮箱 | {{用户邮箱}} |
| 方案 | {{订阅方案}} |
```

### 在 HTML 中

```html
<div class="{{theme_class}}">
  <span id="user-{{user_id}}">{{display_name}}</span>
</div>
```
